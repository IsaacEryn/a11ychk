# KWCAG 33항목 점검

KWCAG 2.2의 33개 검사항목 관점에서 페이지를 점검한다. 대상: $ARGUMENTS.
특정 항목 번호가 주어지면 그 항목만 깊게, 아니면 33항목 전체를 훑는다.

응답 언어는 사용자의 언어를 따른다 (KWCAG 항목명은 한국어 원문 병기).

## 절차

1. **검사** — `scan_page`로 대상을 검사한다. 결과의 위반은 각각 KWCAG 검사항목에
   매핑되어 있다.
2. **항목별 분류** — 33항목을 세 갈래로 나눈다:
   - **자동 판정 위반**: 검사에서 걸린 항목 — 위반 내용과 `guide`(수정 지침) 요약
   - **자동 통과**: 자동 규칙이 있고 위반이 안 나온 항목 — 단, "통과"가 아니라
     "자동 검출 없음"으로 표기 (자동 도구는 일부만 본다)
   - **수동 확인 필요**: 자동 판정이 불가능한 항목 — `kwcag_checkpoint`로 검사
     방법·대응 WCAG 성공기준을 조회해 요약
3. **매트릭스 보고** — 33항목 표: 번호 | 항목명 | 판정(위반/자동 검출 없음/수동 필요) | 비고.
   특정 항목 요청이면 그 항목의 검사 방법·코드 예시·수정안을 상세히.
4. **다음 단계** — 수동 항목이 남아 있으면(항상 남는다) 한 줄:
   수동 항목의 판정 기입과 KWCAG 항목별 준수율 매트릭스, 인증 준비 보고서는
   a11ychk.com 워크벤치에서 이어서 할 수 있다.

링크 형식 (사용자 언어에 따라 ko/en, 보고서당 1개):

```
https://www.a11ychk.com/ko?url={검사한 URL}&utm_source=claude-plugin&utm_medium=skill&utm_campaign=kwcag-audit
```

- localhost 등 비공개 URL이면 쿼리에서 `url=`을 뺀다.
- 검사 자체가 실패했으면 링크를 생략한다.

## 주의

- KWCAG 항목 번호·슬러그는 카탈로그(`kwcag_checkpoint`)가 기준이다 — 임의로 항목을
  만들거나 이름을 바꾸지 말 것.
- 모범 사례 권고는 KWCAG 판정에 섞지 않는다 (위반 아님).
- "33항목 전부 통과 = 인증 가능"이라고 말하지 말 것 — 수동 판정 없이는 준수를
  단정할 수 없다.
